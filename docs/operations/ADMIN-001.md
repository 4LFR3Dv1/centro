# ADMIN-001 — Operational Constitution

Status: `CHECKPOINT C3 — POSTGRES_WITNESS_CANDIDATE`

Program ledger: issue #26.

## Authority of this cut

ADMIN-001 establishes the durable operational substrate for students, enrollments, credentials, staff sessions and audit. It does **not** create enrollment UI, student login UI, lessons, scheduling, process milestones or generated documents.

## Constitutional invariants

```text
PUBLIC VISITOR != STUDENT
STUDENT STATE REQUIRES ENROLLMENT
Student != Enrollment
CPF/document != login identity
plaintext password != durable state
session has exactly one subject
FIRST_LICENSE + D = invalid
audit actor identity is explicit
```

### Student identity

- Internal identity: UUID generated by the application.
- Human login identity: `students.public_id`.
- Public format: `CEN-YY-NNNNN...`.
- Public ID numbering is backed by `student_public_id_seq` and formatted by application code using the São Paulo calendar year.
- Document/CPF may be retained as administrative data when necessary, but is never an authentication identifier.

### Enrollment

A Student may have several Enrollments over time. Supported initial service types:

- `FIRST_LICENSE`
- `CATEGORY_ADDITION`
- `CATEGORY_CHANGE`
- `LICENSED_TRAINING`

Supported operational categories in the first schema: `A`, `B`, `AB`, `D`.

The database itself rejects `FIRST_LICENSE + D`.

### Credentials

Student and staff credentials are separated. Credential tables only accept password hashes.

Initial student password contract:

```text
crypto.randomBytes
  ↓
12 symbols / 60 bits from a 32-symbol human-safe alphabet
  ↓
XXXX-XXXX-XXXX
  ↓
Argon2id
  ↓
student_credentials.password_hash
```

The plaintext password is an ephemeral enrollment receipt. No durable column exists for `password`, `initial_password` or `plaintext_password`.

### Sessions

- Session token: 256 random bits.
- Durable representation: SHA-256 token digest only.
- One session belongs to exactly one subject: Student or Staff.
- A session cannot impersonate both.

### Migrations

`server/db/migrate.ts`:

- requires `DATABASE_URL`;
- serializes migration writers with a PostgreSQL advisory lock;
- records applied migrations in `schema_migrations`;
- wraps each migration in its own transaction;
- is expected to be idempotent when re-run.

### Audit

Every future operational mutation must be able to emit an `AuditEvent` with an explicit actor (`SYSTEM`, `STUDENT`, or `STAFF`) and target entity.

## C3 CI witness

CI provisions a clean PostgreSQL 17 service before any external Detran ingestion and executes:

```text
npm run db:migrate
npm run db:migrate
npm run ops:check
```

The PostgreSQL constitution test then attempts to violate the schema and requires rejection of:

- enrollment with unknown Student;
- first-license category D;
- non-institutional student public ID;
- duplicate StudentCredential;
- Session with Student + Staff simultaneously;
- AuditEvent with contradictory actor identity.

It also inspects `student_credentials` and requires the absence of plaintext-password columns.
