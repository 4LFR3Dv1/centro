# ADMIN-001 — Operational Constitution

Status: `CHECKPOINT C1 — SCHEMA_CONTRACTS_MATERIALIZED`

Program ledger: issue #26.

## Authority of this cut

ADMIN-001 establishes the durable operational substrate for students, enrollments, credentials, staff sessions and audit. It does **not** create enrollment UI, student login UI, lessons, scheduling, process milestones or generated documents.

## Constitutional invariants

```text
PUBLIC VISITOR != STUDENT
STUDENT STATE REQUIRES ENROLLMENT
Student != Enrollment
CPF/document != login identity
plaintext password != durable state
session has exactly one subject
FIRST_LICENSE + D = invalid
audit actor identity is explicit
```

### Student identity

- Internal identity: UUID generated by the application.
- Human login identity: `students.public_id`.
- Public format: `CEN-YY-NNNNN...`.
- Document/CPF may be retained as administrative data when necessary, but is never an authentication identifier.

### Enrollment

A Student may have several Enrollments over time. Supported initial service types:

- `FIRST_LICENSE`
- `CATEGORY_ADDITION`
- `CATEGORY_CHANGE`
- `LICENSED_TRAINING`

Supported operational categories in the first schema: `A`, `B`, `AB`, `D`.

The database itself rejects `FIRST_LICENSE + D`.

### Credentials

Student and staff credentials are separated. Credential tables only accept password hashes. The initial password plaintext is an ephemeral enrollment receipt and is not an attribute of Student or Enrollment.

### Sessions

One session belongs to exactly one subject: Student or Staff. A session cannot impersonate both.

### Audit

Every future operational mutation must be able to emit an `AuditEvent` with an explicit actor (`SYSTEM`, `STUDENT`, or `STAFF`) and target entity.
